## 四、阶段3：V2版本（第一次重大修正）

### 4.1 AI建议汇总
咨询了豆包和Gemini两个AI，发现了3个致命问题：

#### 问题1：AS5600的I2C地址冲突（最严重）
```
问题描述：
- AS5600的I2C地址固定为0x36，无法修改
- 每个手指节点需要3个编码器（3个关节）
- 3个AS5600挂在同一条I2C总线上
- 地址冲突，完全无法通信

解决方案：
- 砍掉AS5600
- 使用N20电机自带的内置霍尔编码器
- 内置编码器：6脉冲/转
- 经4倍频后：24脉冲/转
- 经100:1减速比后：2400脉冲/圈
- 分辨率：360°/2400 = 0.15°，足够PID闭环
```

#### 问题2：HX711用错传感器
```
问题描述：
- HX711是为称重传感器设计的24位高精度ADC
- FSR402的信号强度远大于称重传感器
- 信号强度差几个数量级，HX711完全浪费

解决方案：
- 砍掉HX711
- FSR402 + 10kΩ电阻组成分压电路
- 直接接入STM32F103的内部12位ADC
- 响应速度更快，代码更简单
```

#### 问题3：TB6612数量不够
```
问题描述：
- 每个TB6612只能驱动2路电机
- 每个手指节点需要控制3个关节 = 3路电机
- 每个节点需要2个TB6612（其中1路闲置）
- 5个节点 × 2 = 10个TB6612

解决方案：
- TB6612数量从8个改为10个
```

### 4.2 其他修正

## 五、阶段4：V3版本（引脚冲突修正）

### 5.1 AI建议汇总
再次咨询豆包和Gemini，发现了引脚分配的致命冲突：

#### 问题1：PA0重复复用
```
问题描述：
- V2文档中PA0同时分配给：
  - 电机1的PWM输出
  - FSR传感器的ADC输入
- PWM信号会干扰ADC读数
- 无法同时工作

解决方案：
- FSR改到PA2（ADC1_CH2）
- PA0专做TIM2_CH1（编码器）
```

#### 问题2：定时器编码器接口限制
```
问题描述：
- STM32的通用定时器只有CH1和CH2支持硬件编码器接口模式
- CH3和CH4只能做普通输入捕获或PWM输出
- V2中电机2/3编码器分配到了TIM3_CH3/CH4，无法工作

解决方案：
- 电机1编码器：PA6/PA7 (TIM3_CH1/CH2)
- 电机2编码器：PA0/PA1 (TIM2_CH1/CH2)
- 电机3编码器：PA8/PA9 (TIM1_CH1/CH2)
- 注意：TIM1是高级定时器，需开启BDTR时钟
```

### 5.3 控制算法完善

#### PID参数（初始值）
```c
#define PID_KP  5.0f    // 从5开始试
#define PID_KI  0.0f    // 位置控制通常不需要
#define PID_KD  0.5f    // 抑制超调
```

#### PID整定步骤
```
1. 设KI=0, KD=0.5, KP从1.0开始
2. 逐渐增大KP，直到手指开始振荡
3. 将振荡时的KP乘以0.6作为最终值
4. 保持KP不变，逐渐增大KD消除超调
5. 位置控制通常不需要KI
```

#### 死区补偿
```c
#define DEAD_ZONE  300   // 约15% PWM

int16_t deadzone_compensate(int16_t pid_output) {
    if (pid_output > 0 && pid_output < DEAD_ZONE) {
        return DEAD_ZONE;
    } else if (pid_output < 0 && pid_output > -DEAD_ZONE) {
        return -DEAD_ZONE;
    }
    return pid_output;
}
```

## 六、阶段5：V3.1版本（工程细节修正）

### 6.1 AI建议汇总

第三次咨询豆包和Gemini，发现了5个工程细节问题：

#### 问题1：LM2596压差问题（致命）
```
问题描述：
- LM2596压差约1.5V
- 5V输入时，3.3V输出不稳定
- 电机启动时5V总线跌落至4.5V
- LM2596停止工作，STM32复位

解决方案：
- 砍掉LM2596
- 改用AMS1117-3.3线性稳压器
- 压差仅1.1V，5V输入完全够
- 纹波抑制更好，给STM32更干净的3.3V
```

#### 问题2：电流检测无法实现
```
问题描述：
- TB6612FNG没有电流反馈引脚
- 代码中写的电流检测无法工作

解决方案：
- 删除电流检测代码
- 改用编码器位置变化判断堵转
- 如果300ms内编码器无变化，判定堵转
```

#### 问题3：保险丝响应太慢
```
问题描述：
- 0.3A自恢复保险丝响应时间数百毫秒
- 无法保护N20减速箱齿轮
- 堵转时可能已损坏机械结构

解决方案：
- PTC只能防短路火灾
- 机械保护依赖软件快速响应
- 50ms内检测到堵转立即关闭PWM
```

#### 问题4：杜邦线不抗弯折
```
问题描述：
- 杜邦线内部多股普通铜线
- 压接处脆弱，无抗疲劳弯折能力
- 关节反复运动后内部断裂
- 导致编码器丢步、电机停转

解决方案：
- 面包板调试阶段用杜邦线
- 最终组装用26AWG高柔性硅胶线
- 耐弯折数万次
```

#### 问题5：尼龙联轴器滑丝
```
问题描述：
- 尼龙材料太软
- 金属顶丝拧进尼龙螺纹容易滑丝
- 受到反向冲击力时顶丝滑移
- 久而久之内孔铰成圆形

解决方案：
- 改用金属顶丝联轴器（黄铜/铝合金）
- 金属螺纹可承受极大锁紧力
- 顶丝死死咬在D形轴平面上
```

### 6.2 其他优化建议

#### 豆包补充建议
```
1. TB6612 STBY引脚接3.3V（避免休眠）
2. FSR并联0.1μF瓷片电容（滤50Hz干扰）
3. CAN用4芯屏蔽排线（抗干扰）
4. 上电顺序：先3.3V再5V
5. TIM1编码器需开启BDTR时钟
6. 逻辑分析仪暂时不买（省钱）
7. FSR力曲线作为答辩亮点
8. 3D手掌底板预留线槽
```

## 八、最终方案总结

### 8.1 系统架构
```
PC端：
  USB摄像头 → YOLOv8-pose(21关键点) → 角度映射(5指×3关节) → UART发送

主控板(STM32F407)：
  UART接收 → CAN广播(1Mbps)

手指节点(STM32F103 ×5)：
  CAN接收 → PID控制 → TB6612驱动 → N20电机
  ↑
  内置霍尔编码器(位置反馈) + FSR402(触觉反馈)
```

### 8.2 关键参数
| 参数 | 值 |
|------|-----|
| 电机电压 | 6V |
| 电机转速 | 100RPM |
| 传动比 | 1:1直接驱动 |
| 编码器分辨率 | 2400脉冲/圈（0.15°） |
| CAN波特率 | 1Mbps |
| 控制周期 | 100Hz |
| PID参数 | KP=5, KI=0, KD=0.5 |
| 死区补偿 | 15-20% PWM |

### 8.3 引脚分配
```
手指节点(STM32F103C8T6)：
  电机PWM: PB6/PB7/PB8 (TIM4_CH1/2/3)
  电机方向: PB10-PB15 (GPIO)
```

## 十二、需要其他AI验证的问题

### 12.1 架构验证
```
1. 分布式CAN总线架构是否合理？
   - 1个主控(STM32F407) + 5个节点(STM32F103)
   - CAN总线1Mbps，100Hz控制周期
   - 负载率约5%，远低于30%安全阈值

2. 为什么不集中式控制？
   - 15个电机需要100多根导线
   - 线束丛林，机械上易卡死、断线
   - 分布式只需4根总线（VCC/GND/CAN_H/CAN_L）
```

### 12.2 电机选型验证
```
3. N20 6V 100RPM是否合适？
   - 关节运动90°约0.15秒
   - 经100:1减速比后扭矩足够
   - 内置霍尔编码器2400脉冲/圈，分辨率0.15°

4. 1:1直接驱动是否可行？
   - N20已有100:1内置减速
   - 外部再加传动比意义不大
   - 直接驱动简化机械设计
```

### 12.3 电路设计验证
```
5. AMS1117-3.3供电方案是否稳定？
   - 5V输入，3.3V输出，压差1.7V
   - 压差仅1.1V，完全够
   - 纹波抑制比LM2596更好

6. FSR分压电路是否正确？
   - FSR402 + 10kΩ分压
   - 未受力时ADC≈0V
   - 重压时ADC≈3.0V
   - 匹配STM32的0-3.3V ADC范围

7. CAN终端电阻接法是否正确？
   - 仅主控和最远节点各接120Ω
   - 中间节点不接
   - 避免总线等效电阻过低
```

### 12.4 控制算法验证
```
8. PID参数是否合理？
   - 初始值：KP=5, KI=0, KD=0.5
   - 位置控制通常不需要KI
   - 现场微调

9. 死区补偿方案是否正确？
   - 15-20% PWM死区
   - 低于死区时强制输出死区值
   - 解决N20低电压不转问题

10. 堵转保护方案是否可行？
    - TB6612无电流反馈引脚
    - 改用编码器位置变化检测
    - 300ms内无变化判定堵转
```

### 12.5 机械设计验证
```
11. 3D打印材料选择是否正确？
    - PETG或ABS，不用PLA
    - PLA会蠕变变形
    - 壁厚2mm，关键部位3-4mm

12. 联轴器选择是否正确？
    - 3mm金属顶丝联轴器
    - 顶丝顶在D形轴平面上
    - 避免尼龙滑丝

13. 关节线材选择是否正确？
    - 26AWG高柔性硅胶线
    - 耐弯折数万次
    - 避免杜邦线断裂
```

### 12.6 系统集成验证
```
14. 调试顺序是否合理？
    - 自底向上，先单元后集成
    - 先空载后加载
    - 先单节点后全系统

15. 上电顺序是否正确？
    - 先3.3V单片机电源
    - 再5V电机电源
    - 断电反之

16. 通信协议是否完善？
    - UART: 13字节帧，含帧头帧尾CRC
    - CAN: 标准帧，5个手指ID
    - 编码器: 2400脉冲/圈
```
