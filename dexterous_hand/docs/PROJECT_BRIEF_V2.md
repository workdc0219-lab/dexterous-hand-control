## 六、关键设计决策

### 6.1 为什么砍掉AS5600？

**问题**：AS5600的I2C地址固定为0x36，无法通过硬件或软件修改。

**影响**：
- 每个手指节点需要3个编码器（3个关节）
- 3个AS5600挂在同一条I2C总线上
- 地址冲突，完全无法通信

**解决方案**：
- 使用N20电机自带的内置霍尔编码器
- 内置编码器：6脉冲/转
- 经1:100减速比后：600脉冲/圈
- 精度完全满足毕设需求

### 6.2 为什么砍掉HX711？

**问题**：HX711是为称重传感器设计的24位高精度ADC。

**影响**：
- FSR402的信号强度远大于称重传感器（几百欧~几兆欧 vs 微欧级）
- HX711的高精度完全浪费
- 增加成本和复杂度

**解决方案**：
- FSR402 + 10kΩ电阻组成分压电路
- 直接接入STM32F103的内部12位ADC
- 响应速度更快，代码更简单

### 6.3 为什么电源要5V 10A？

**电流估算**：
- N20空载电流：约0.2A/个
- 15个电机空载：约3A
- N20堵转电流：约0.5-0.8A/个
- 15个电机堵转：约7.5-12A

**风险**：
- 5V 3A电源在多指同时抓取时会欠压
- 导致STM32主控复位
- 系统不稳定

**解决方案**：
- 使用5V 10A（50W）开关电源
- 预留足够余量
- 成本仅增加约¥10

### 6.4 为什么TB6612需要10个？

**计算**：
- 每个TB6612驱动2路电机
- 每个手指节点控制3个关节 = 3路电机
- 每个节点需要2个TB6612（其中1路闲置）
- 5个节点 × 2 = 10个TB6612

### 6.5 为什么用PETG/ABS而不是PLA？

**PLA问题**：
- 韧性差，容易断裂
- 持续受力下会蠕变（变形）
- 耐热性差

**PETG/ABS优势**：
- 韧性好，不易断裂
- 抗蠕变性能好
- 耐热性更好
- 适合承受持续力的机械结构

## 八、通信协议详情

### 8.1 UART协议（PC→主控板）

```
波特率：115200 bps
数据格式：8N1

帧格式（13字节）：
[0xAA] [angle0_L] [angle0_H] ... [angle4_L] [angle4_H] [CRC8] [0x55]

- 0xAA：帧头
- angle0~angle4：5个手指角度（0-180度，各2字节）
- CRC8：校验
- 0x55：帧尾
```

### 8.2 CAN协议（主控板→手指节点）

```
波特率：1 Mbps
帧格式：标准帧（11位ID）

CAN ID分配：
- 0x001：手指1（大拇指）
- 0x002：手指2（食指）
- 0x003：手指3（中指）
- 0x004：手指4（无名指）
- 0x005：手指5（小指）

数据帧（8字节）：
[Byte0-1]：关节1角度（0-180度）
[Byte2-3]：关节2角度（0-180度）
[Byte4-5]：关节3角度（0-180度）
[Byte6]：CRC校验
[Byte7]：保留

负载率估算：
- 100Hz控制周期
- 每帧约100bit（含开销）
- 负载率 = 5×100×100 / 1000000 = 5%（远低于30%安全阈值）
```

### 8.3 编码器接口（内置霍尔）

```
接口类型：脉冲输出（A/B相）
分辨率：6脉冲/转（电机端）
经1:100减速比后：600脉冲/圈（关节端）

接线：
- 电机编码器A相 → STM32 TIMx_CH1
- 电机编码器B相 → STM32 TIMx_CH2
- 配置为编码器模式，硬件自动计数
```
